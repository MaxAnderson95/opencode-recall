# Effect v4 and Effect Schema for the hub, plugin, protocol, and eval

The hub, the plugin, the protocol client, and the eval are written in Effect v4 (`effect`, pinned exactly; 4.0.0-rc.117 when adopted), and every boundary schema is Effect Schema; zod is not a dependency. The uploader, the embedding queue, and the upcoming work in #24 to #31 are mostly concurrent background work with timers, retries, backoff, single-flight runs, and shutdown ordering. Hand-rolled with `setTimeout`, flags, and thrown errors, each of those rules was re-implemented per module and failures were untyped. Effect gives them one model: services and layers for wiring, `Schema.TaggedError` failures in the type, `Schedule` for retry and backoff, fibers owned by a layer's scope for background work, and `Config`/`ConfigProvider` for environment reads that tests replace without touching `process.env`.

## Consequences

- Each module is a service (`Archive`, `Embedder`, `EmbedQueue`, `HubConfig`, `PluginConfig`, `Source`, `Storage`, `Uploader`) with a `Layer` that acquires and releases what it owns. `Archive` still owns every SQL statement; its methods are thin `Effect.fn` wrappers over the same synchronous `bun:sqlite` transactions.
- Effects run only at the edges. `main.ts` launches the hub layer with `Layer.launch` and interrupts it on SIGINT/SIGTERM; `Bun.serve` gets a plain `(Request) => Promise<Response>` built by `makeHandler`, which captures its services once and runs each request with `Effect.runPromiseWith`. The OpenCode plugin uses OpenCode's promise plugin API: `setup` builds a `ManagedRuntime` from the plugin's layers and returns `runtime.dispose()` as its cleanup, and the `recall_search` tool's `execute` runs its effect the same way `makeHandler` does.
- OpenCode 2.0.14 also has an Effect plugin API, but it hands the plugin values of the host's own `effect` build (the SDK pins 4.0.0-rc.112), so a plugin on another Effect version would mix two runtimes. The promise API keeps the plugin's Effect version independent of OpenCode's.
- Anything the runtime runs must see the logger and `ConfigProvider` in the runtime's own context (`Layer.provideMerge`), not only in a layer's build, because fibers forked from `runtime.runPromise` inherit the runtime context.
- Request strictness is a decode option, not a schema property: `decodeRequest` decodes with `onExcessProperty: "error"`, which is how unknown fields stay rejected on the wire. The wire format and `PROTOCOL_VERSION` did not change with the port.
- The protocol client is a plain constructor, `makeClient`, returning Effect-valued verbs that fail with `HubError` or `TransportError`, because the plugin rebuilds it from freshly read config on every pass. It wraps `fetch` rather than Effect's `HttpClient`, which lives in `effect/unstable` and would add nothing the uploader's own retry policy does not already decide.
- Tests stay on `bun test`. Tests that exercise time use `TestClock` from `effect/testing`; the uploader tests stay on the real clock because they run a real HTTP hub.
